# Auto Exam — тренажер ПДР

Статичний сайт без збірки й залежностей. Деплой: GitHub Pages через workflow `.github/workflows/pages.yml` (викладає корінь гілки `main`) → https://marynashavlak.github.io/auto-exam/. Кожен push у `main` одразу публікується, тому нові функції робимо в окремих гілках.

## Файли

- `index.html` — лише розмітка: шапка, картки наборів (`.batch-card[data-scope]`), статистика, порожній `<main id="panel">`.
- `styles.css` — усі стилі. Блоки додавались шарами під кожну функцію, тому деякі правила (`.batch-cards`) перевизначаються нижче.
- `app.js` — уся логіка, чистий JS без модулів (глобальні `const`/функції).
- `questions.js` — `const questions=[...]`, одне питання на рядок. Шукати питання: `grep '"id":42,' questions.js`.
- `img/` — картинки WebP: `q042-diagram.webp`, `q042-original.webp`, `q042-note-1.webp`.

Скрипти підключені звичайними `<script src>` (не `fetch`), щоб сайт відкривався й із диска через `file://`.

## Формат питання

`{id, question, answers[], correct, diagram, original, notes[], batch, batchOrdinal, also?}`
- `correct` — індекс у `answers` (з 0). У UI показується оригінальний номер `index+1`, бо є варіанти типу «1 і 2».
- `diagram` — `img/...` або `null` (тоді без картинки). `original` є завжди, показується після відповіді. `notes` — додаткові пояснення (є лише в кількох питаннях).
- `id` — 1…334 з пропусками; на `id` прив'язані закладки й статистика користувачів, тому їх не перенумеровувати.
- `batch` — `batch1`…`batch10`, `batchOrdinal` — номер у порції. Власні назви порцій — `BATCH_TITLES` в `app.js` (`batch10` = «Фінальні помилки»), без назви — «Порція N» (`batchName`).
- `also` — необов’язково: `[{batch, batchOrdinal}]`, інші порції, куди входить це ж питання з тим самим `id` (так у «Фінальні помилки» включені вже наявні питання — закладки, коментарі й статистика спільні, в «Усіх питаннях» без дублів). Усі місця питання — `batchPlaces(q)`.

## Логіка (`app.js`)

- Набори (scope): `batch1..10`, `all`, `saved`, `mistakes`, `commented` (питання з моїми коментарями, `reconcileCommentedSession`), `mix:batch1+batch3`. Списки в `SCOPE_IDS`, назви в `SCOPE_NAMES`; мікси створює `ensureMixedScope`.
- Сесія набору: `{order, index, answers, seen, mode:'normal'|'review'}`; перевірка — `cleanSession`. Кожен набір має окремий прогрес у `root.sessions`. `seen` — id відкритих питань (позначає `markSeen()` у `render()`).
- Пагінація (`renderPager`) — стрічка в один рядок (`layoutPagers` підганяє ширину під ціле число кнопок, ‹ › гортають по сторінці) з номерами 1…N поточного набору з класами `correct` / `wrong` / `skipped` (відкривали без відповіді) / `unseen` + `current`; є над питанням і на екрані результатів. Під нею — навігація (`.foot`: ← Попереднє / Пропустити / Наступне), теж над питанням, щоб кнопки не стрибали від висоти питання. Новий спосіб створити `state` — не забувати `seen:[]`.
- `render()` щоразу перебудовує всю панель; DOM будується через `h(tag, props, children)` і `button(text, css, handler, disabled)`; повідомлення — `notice()`.
- Спільні помічники: `fileButton()` (кнопка + прихований `<input type=file>`), `downloadJson()` (експорт), `syncSessionOrder()` (підгонка сесії під новий список id), `questionLabel(q, scope?)` («Порція N · №M»; у порції з `also` — номер у ній).
- Підтвердження дій — лише `await askConfirm(text, {title, ok, cancel, danger})` (власне вікно на `<dialog>`), не `window.confirm`. Для руйнівних дій `danger:true`.
- Відповідь → `recordAttempt(id, isCorrect)` — єдине місце оновлення статистики помилок (помилка → 0/3, `MASTERED_AT=3` правильних поспіль → засвоєно).
- Порядок відповідей перемішується при кожному завантаженні сторінки (`createAnswerOrders`).

## Мої коментарі (блок «Мої коментарі до питань» в `app.js`)

- Кнопка «📝 Додати коментар / Мій коментар» у заголовку кожного питання в будь-якому наборі (`commentButton`); секція під питанням — `renderComment`. До відповіді коментар захований, після відповіді показується сам.
- Редактор — `contenteditable` + `document.execCommand` (панель `COMMENT_TOOLS`, іконки `COMMENT_ICONS`), без бібліотек. Tab/Shift+Tab — відступи.
- Увесь HTML коментаря проходить через `cleanCommentHtml` (білий список тегів і стилів) — при вставці, збереженні, завантаженні й імпорті. Не вставляти HTML коментаря в DOM в обхід нього.
- Чернетки — `commentDrafts` (у пам’яті, переживають перехід між питаннями; при закритті вкладки з незбереженим — попередження).
- Картинки зменшуються до 1600 px у WebP (`shrinkImage`) і зберігаються як Blob.
- Експорт/імпорт — JSON `{type:'pdr-comments', version:1, records:{id:{html, images:[dataURL], updatedAt}}}` (панель `#comments-bar` під питанням). Запис ↔ JSON — `commentRecord` / `storeCommentRecord`.
- Відоме обмеження Chrome: колір у тексті, вставленому з буфера всередину пункту списку, губиться (жирний/курсив/маркер зберігаються).

## Синхронізація між пристроями (блок «Синхронізація… GitHub Gist» в `app.js`)

- Синхронізуються коментарі, закладки й найчастіші помилки; прогрес порцій — ні (свідомо). Токен GitHub з дозволом `gist`, панель і вікно налаштування — у `#comments-bar` (`openSyncSetup`).
- Два секретні gist (`SYNC_GISTS`), `findSyncGist(s, kind)` знаходить їх за файлом-позначкою на інших пристроях (кілька — найстаріший): коментарі (`pdr-comments-sync.json` + `q042.json` на кожне питання у форматі запису експорту) і прогрес (`pdr-progress-sync.json` + `saved.json` `{ids}` + `mistakes.json`). Розділені, щоб часті зміни помилок не тягнули завантаження картинок.
- Злиття трибічне з base (стан на момент останньої синхронізації) — так переносяться й видалення; конфлікт — новіша правка, правка сильніша за видалення. Коментарі — `syncCommentsOnce` (base = updatedAt), закладки й помилки — `syncProgressOnce` + `merge3` (base = відбитки `savedFp`/`mistakeFp`; час зміни помилки — `updatedAt`, ставить `recordAttempt`). Якщо версія gist (`/commits?per_page=1`) не змінилась, gist не завантажується.
- Base лежить поруч із даними, щоб зникати разом із ними: коментарів — в IndexedDB (запис `sync`), закладок і помилок — у localStorage (`pdr-quiz-progress-sync-v1`).
- `syncNow()` — одна синхронізація за раз; `scheduleSync(ms)` — після змін (коментарі й закладки 1,5 с, помилки 15 с); також при завантаженні, поверненні на вкладку, виході з неї, раз на 2 хв і кнопкою. Застосування даних з gist іде під `syncApplying`, щоб не запускати нову синхронізацію. До `commentsReady` не синхронізувати — порожній локальний список виглядав би як видалення.

## Сховище браузера (ключі не змінювати — там дані користувачів)

localStorage: `pdr-quiz-batches-v1` (сесії), `pdr-quiz-saved-questions-v1` (закладки), `pdr-quiz-typical-mistakes-v1` (помилки), `pdr-quiz-batch-answer-layouts-v1` (порядок відповідей), `my-pdr-quiz-standalone-v3` (міграція старої версії), `pdr-quiz-progress-sync-v1` (синхронізація закладок і помилок: `{gistId, version, saved, mistakes}`).
IndexedDB: база `pdr-quiz-comments-v1`, сховище `comments` (ключ — id питання) — мої коментарі з картинками; там же службовий запис `id:'sync'` — налаштування синхронізації `{token, gistId, version, base, at}` (поруч із коментарями навмисно: зникають разом).

## Додавання питань і порцій

- Порції (`BATCHES`), картки порцій, лічильники в шапці й `<title>` будуються з `questions.js` (`renderBatchCards`). Нова порція = нове значення `batchN` у даних.
- Нова порція зі скрінів (як `batch6`): `original` — увесь скрін у WebP, `diagram` — вирізана з нього ліва картинка (або `null`), правильна відповідь — зелена на скріні; перед додаванням звірити з наявними питаннями, дублікати не додавати (виняток — порція, яка має містити всі питання з фото, як `batch10`: наявні питання підключаються через `also`).
- Скріни з телефона (як `batch7`, сайт driver online): `original` — обрізка від картинки/питання до останньої відповіді без шапки й кнопок, `diagram` — картинка над питанням, скрін «Пояснення» до питання — у `notes`. Апостроф у текстах — `’`.
- Нові питання в наявній порції дописуються в кінець сесій користувачів без скидання прогресу (`cleanSession`).
- Після змін у даних: `node tools/check-data.js` (унікальні id, `correct` у межах, усі картинки існують і використовуються).
- Числа відмінюються через `questionsCount(n)` / `batchesCount(n)` (`plural`).

## Стиль коду

Компактний JS у стилі наявного коду (короткі рядки-ланцюжки, `h()`/`button()`), коментарі й увесь текст інтерфейсу українською.
